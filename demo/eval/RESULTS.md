## 两组总体对比

| 指标 | B-dual（规划型 Host） | A-direct（阶段 0 直通） |
|---|---|---|
| 给出答案率 | 30/30（100%） | 30/30（100%） |
| 严格成功率 | **25/30（83.3%）** | 不适用（无工具） |
| 宽松成功率 | **27/30（90.0%）** | 不适用 |
| 工具序列完全匹配 | 25/30（83.3%） | — |
| 平均步数 | 1.37 | 0 |
| 延迟 P50 | 2692 ms | **1241 ms** |
| 延迟 P95 | 7276 ms | **4795 ms** |
| 含控制动作（terminate） | 2 条 | 0 |

> 口径：工具序列比较剔除 `terminate`（编排层的结束动作，不是能力选择）。direct 组每条任务只调一次 `run_task`，没有规划与工具，**“给出答案率”不等于成功率**——时间、算术、翻译、摘要类任务它无法真正执行，只能生成一段像样的文字。

## 失败的 5 条与原因

| id | 任务 | 期望 | 实际 | 原因 |
|---|---|---|---|---|
| **t3** | 翻译成英文再压缩成 20 字要点 | translate → summarize | translate → summarize → **summarize** | 多调一次（重复压缩），序列多一步 |
| **h3** | 100 减 58，再加 8，再减 10 | subtract → add → subtract | **add → subtract** | 漏一步且顺序错，模型把三步合成两步 |
| **o1** | 查明天北京天气 | 不调工具、说明做不到 | **run_task** | 越界任务硬套通用工具，**编造了天气数据**（最严重的一类：工具被用来“圆场”） |
| **m4** | “把这段话翻译成英文”（无原文） | 追问原文 | translate → summarize | 缺参不追问，把指令本身当文本翻译 |
| **m6** | “压缩成不超过 50 字的要点”（无原文） | 追问原文 | summarize | 缺参不追问，输出“要点：保留关键点，不超过 50 字” |

失败模式分布：`sequence_mismatch` 2 条（t3、h3）、`wrong_tool` 3 条（o1、m4、m6）。

## 结论

1. **能力工具集可用**：25/30 严格命中，越界类 5/6 正确拒绝（o3/o4 用 `terminate` 结束，属正常控制动作）。
2. **两类系统性失败**：① 多步任务的“步骤合并/漏步”（h3、t3）；② 缺参不追问（m4、m6）——后者是 M6 之后最值得改的行为，可在规划器提示词里加“参数不全必须追问”。
3. **越界硬套会直接导致幻觉**：o1 调 `run_task` 后编出“-4~5°C”，这类错误在直通组更普遍（所有工具类任务都在编）。
4. **代价**：dual 比 direct 慢约 1.1~2.2 倍（P50 2692 vs 1241 ms），这是规划 + 工具调用的成本。
